### 막힌 점 / 트러블슈팅

- 프로젝트 디렉터리명이 한글(`식집사`)이라 `create-next-app`이 npm 이름 제약으로 실패 → 임시 폴더에 생성 후 파일만 이동, `package.json` name은 `sikjipsa`
- 상위 홈 디렉터리의 `package-lock.json`을 Turbopack 루트로 잡는 경고 → `next.config.ts`에 `turbopack.root` 고정
- 배포 후 열어본 `sikjipsa.vercel.app`이 백지라 빌드 실패로 오판 → **타인이 선점한 도메인**이었음. 이 프로젝트 URL은 `-jungvin`이 붙는 쪽. 판별 근거는 `-jungvin` 계열 3개만 Vercel SSO로 302 리다이렉트된 점
- Vercel Authentication(Standard Protection)이 신규 프로젝트 기본 on → Settings > Deployment Protection에서 해제
- `supabase db push`가 `Access token not provided`로 실패 → CLI가 macOS 키체인의 토큰을 읽으려 할 때 뜬 권한 요청을 거부해서 발생. 허용 후 정상
- 이미지 링크를 curl로 검증하니 45건 중 36건이 429 — Wikimedia가 기본 UA를 레이트리밋. 서술적 User-Agent를 붙이니 45/45 200. 브라우저 렌더도 느렸는데 `Special:FilePath`가 1장당 리다이렉트 2번을 타서 45장이 실제로는 135요청이 되는 구조였음 → CDN 직접 링크로 전량 교체
- `next dev`가 실행될 때마다 `CLAUDE.md` 끝에 Next.js 자체 블록을 덧붙임 → `next.config.ts`에 `agentRules: false`
- 인증 에러 문구를 Supabase 에러 **메시지 문자열**로 매칭했다가 실제 응답에 마침표가 붙어 있어 실패 → `error_code` 기준 매칭으로 변경
- 브라우저 자동완성이 채워둔 값 위에 타이핑이 덧붙어 로그인이 실패 — 앱 버그가 아니라 테스트 절차 문제. 별개로 자동완성이 입력칸을 연파랑으로 덮는 문제는 CSS로 보정
- SC-07 헤더 이미지가 안 보임 → Tailwind에 없는 `size-18` 클래스를 써서 크기가 안 잡혔던 것, `size-16`으로 교체
- 캘린더에서 주간 뷰로 전환하면 선택 날짜가 범위 밖으로 나가 하단 리스트가 엉뚱하게 비어 보임 → 범위가 바뀔 때 오늘(또는 범위 첫날)로 되돌리도록 보정
- 선택 날짜와 오늘이 같은 스타일이라 오늘을 알 수 없었음 → 오늘 칸에 라임 링 추가
- 폰 프레임이 창 높이에 따라 비율이 뭉개지고 내부 UI만 커 보이던 문제 → 안쪽을 430×860으로 고정하고 통째로 축소하는 방식으로 변경

### 스펙과 다르게 구현한 부분 + 이유

- `products` 테이블 미생성 — 구현 착수 순서 2번은 "제품 포함 5개 테이블", CLAUDE.md는 "제품 카탈로그 = 코드 내 JSON"으로 충돌. 제휴사 API 연동 금지·목업 사용이 MVP 범위이므로 JSON 단일 소스로 결정(사용자 확정). 실제 생성은 4개
- 날씨 데이터 테이블 생략 — 구현 착수 순서 2번에 명시된 대로(조회성 데이터)
- `profiles`에 `login_account` 필드 없음 — `auth.users.email`이 이미 보유, 중복 저장 회피
- 회원가입 트리거(`handle_new_user`)는 데이터정의서에 없는 추가 요소 — `auth.users` ↔ `profiles` 1:1 연결을 보장하기 위한 구현 수단
- 위치 저장 형식 — 허용 시 "위도,경도" 문자열, 거부 시 "서울"을 `location` 한 필드에 담음(데이터정의서가 텍스트 단일 필드라 컬럼을 늘리지 않음)
- `photo_url`은 비워둠 — 종류별 기본 이미지를 쓰는 MVP 범위라 `species`로 `plants.json`에서 찾아 사용
- SC-01 에러 문구는 화면설계서에 정의가 없어 임시 문구 — `ERROR_MESSAGES` 한 곳에 모음. **확정 필요**
- 케어현황 링 3개의 의미가 정의돼 있지 않아 임의 정의 — 물주기·분갈이는 오늘 처리 대상 중 완료 비율, 화분위치는 종별 권장 광량과 배치가 일치하는 식물 비율. **확정 필요**
- 장마 판정 — 정책은 "일 강수량 20mm 이상"인데 API가 시간당 값만 줘서 20mm/24h로 환산. "3일 연속 강수"는 과거 이력이 필요해 미구현
- 날씨 예외 동시 충족 시 우선순위가 정책정의서에 없어 기온 예외(폭염→한파)를 먼저 판정. **확정 필요**
- 캘린더 "날짜별 날씨 아이콘"은 오늘 칸에만 — 과거·미래 일별 날씨는 유료 History API가 필요, 유료 API 금지 제약과 충돌
- "날짜별 식물 배지(색상 구분)" 기준이 없어 케어 유형으로 구분. **확정 필요**
- 케어 리포트 지표 정의가 없어 임의 정의 — 주간 완료율(최근 7일)·연속 관리일수(오늘 안 했어도 어제까지 이어졌으면 유지). **확정 필요**
- SC-03에 화면설계서 구성요소에 없는 요소 3개 추가 — 식물 선택 가로 탭 · 다가오는 일정 · 날씨 상태별 팁. 메인 탭 정보량 보강 요청에 따른 것, 팁 문구도 신규 작성. **확정 필요**
- SC-09의 "카탈로그 조회 실패" 에러 분기 미구현 — 제품이 코드 내 JSON이라 조회 실패가 발생할 수 없음
- 회원탈퇴에서 계정(`auth.users`) 자체 삭제 미구현 — service_role 키가 필요해 별도 서버 함수가 있어야 함. 현재는 식물을 '삭제' 상태로 바꾸고 로그아웃까지. 30일 유예 파기도 스케줄러가 필요해 범위 밖
- 식물별 알림 on/off 미구현 — 데이터정의서의 알림 권한이 사용자 단위 필드 하나뿐이라 새 필드가 필요, 사용자 판단으로 보류
